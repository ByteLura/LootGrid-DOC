Saving and JSON

LootGrid state is plain serializable data — that is the integration surface for whatever save system your game already uses.

Capture and restore

var data = InventorySerializer.CaptureAll(containers, loadout.Equipment);
string json = InventorySerializer.ToJson(data);
// ... store the string wherever your save system stores strings ...
var restored = InventorySerializer.FromJson(json);
var warnings = new List<string>();
InventorySerializer.RestoreAll(restored, containers, loadout.Equipment, database, warnings);
  • Containers are matched to their saves by Container Id — keep ids unique and stable across versions.
  • Items are matched by definition Id from your Item Database.

Defensive restore

Restore never throws on bad content and never silently loses an item:

  • An entry whose Id is not in the database is skipped with a warning naming the Id; every other entry still restores.
  • An entry that no longer fits its container (you shrank the grid, or the item grew) is skipped with a warning naming it; the rest still restore.
  • The warnings list is the report — surface it in your debug UI or log during development.

Equipment state captures and restores in the same call pair (CaptureEquipment / RestoreEquipment are also available on their own).

What is not claimed

This is not a save system: no slots, no files, no cloud. It produces data — plain DTOs with a JSON form — that a save system can store. That narrower statement is the true one, and it is the one the documentation makes.
