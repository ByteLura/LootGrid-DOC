API Summary

Namespaces: ByteLura.LootGrid (runtime), ByteLura.LootGrid.Editor (workshop), ByteLura.LootGrid.Samples (demo driver). The shipped Documentation~/ApiReference.md in the package is the full reference; this page is the map.

Items

  • ItemDefinition — Id (the save key), DisplayName, Width/Height, CanRotate, Stackable/MaxStack, Rarity, Weight, BaseValue, Category, EquipmentSlot, Icon.
  • ItemStack — a definition + a count; ItemDatabase — the definition registry with Validate(out errors) naming every problem.

The grid — InventoryGrid

TryPlaceAt, TryAdd, Remove, Reduce, Move, Rotate, SplitStack, AutoStack, Sort(mode), CanPlaceAt, CountThatFits, OccupantAt, Items, TotalUnits, TotalWeight, MaxWeight. Mutations report outcomes (moved counts, unplaced counts, bools) — model errors are return values, never exceptions across a drag or a restore.

Containers and transfer

  • InventoryContainer — Grid, DisplayName, ContainerId, Changed.
  • ItemTransfer.TransferAll(source, destination) — fit-checked, conserving, returns units moved.

Equipment (separable module)

  • EquipmentSet — CanEquip, TryEquip, Unequip, GetEquipped, AllSlots; EquipmentLoadout — its MonoBehaviour face with StartingEquipped.

Database and loot

  • LootTable.Generate(System.Random, rolls) — seeded, weighted, range-counted, MaxStack-respecting.

Saves

  • InventorySerializer — Capture / Restore per container, CaptureEquipment / RestoreEquipment, CaptureAll / RestoreAll, ToJson / FromJson. Restore is defensive: named warnings, no throws, no silent loss.

Views

  • InventoryScreenView.Build(...), ContainerPanelView, InventoryGridView, InventoryItemView, EquipmentDollView, InventoryDragController (OnItemClicked, OnGridClicked, TryEquipSelected, RotateSelectionOrDrag), InventoryTheme.
